# Personal Learning Plan

## Profile

- AI: 有基础
- Web3: 新手
- Programming: 无代码
- Goal: Hackathon
- Time budget: 1 小时/天

## North Star

Build enough AI × Web3 literacy and prototype ability to participate in a hackathon with a clear problem, user, demo story, and AI-assisted no-code/low-code prototype.

## Operating Rules

1. Study in public through this GitHub learning repository.
2. Keep daily outputs small, concrete, and commit-ready.
3. Turn every confusing Handbook point into feedback.
4. Prefer no-code or AI-assisted workflows before writing code.
5. Optimize for hackathon usefulness: problem, user, evidence, demo, pitch.

## Daily 1-Hour Routine

- 10 min: review yesterday's notes and choose today's task.
- 25 min: read Handbook/program material or watch assigned content.
- 15 min: produce one artifact: note, task answer, prototype idea, prompt, or diagram.
- 10 min: write daily check-in and capture Handbook feedback.

## Week 1 — Orientation and Web3 Basics

Goal: understand AI × Web3 School workflow, repo habits, and core Web3 terms.

- Set up learning repo and daily check-in loop.
- Build a glossary for wallet, chain, transaction, gas, token, smart contract, dApp, DAO.
- Create first hackathon problem inventory with at least 5 candidate problems.
- Record all Handbook confusion in `handbook-feedback/`.

## Week 2 — AI × Web3 Use Cases

Goal: connect AI abilities to Web3 scenarios.

- Collect 10 AI × Web3 project examples.
- Classify examples by user, pain point, trust layer, and AI role.
- Draft 3 hackathon ideas using a problem-solution-user format.
- Pick 1 idea for deeper validation.

## Week 3 — Prototype and Demo Narrative

Goal: turn one idea into a demo-ready concept.

- Define user journey and core feature list.
- Build a no-code/AI-assisted clickable demo or workflow mock.
- Prepare a demo script and pitch outline.
- Identify risks: data, wallet UX, smart contract dependency, feasibility.

## Week 4 — Hackathon Packaging

Goal: prepare a credible hackathon submission package.

- Finalize README, demo story, screenshots, and pitch.
- Write project one-liner, problem statement, solution, and roadmap.
- Prepare submission checklist in `submissions/`.
- Review feedback and unresolved blockers.
